# Production /app Studio shell implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans task-by-task. Checkboxes track execution. This assignment writes a plan only: no production edits, agents, branches, commits or pushes.

**Goal:** Put the approved Studio interface on the actual `/app` route, using the real retained-source Rust worker for one functioning Characters look, four controls, local images, history/compare/zoom and honest PNG/JPEG export.

**Architecture:** A testable controller owns validated project transitions and resource lifetimes; React renders its state through focused shell components. Source identity, full rendered frame and view transforms remain separate. The first Characters binding depends on profile Tasks2–5; shell/controller work may proceed against typed test doubles, but product/browser acceptance requires the actual module worker, built WASM, calibrated atlas and Rust backdrop.

**Tech Stack:** Installed Next16.4.2/React19/TypeScript, existing render service/profile/project contracts, Canvas encoding, Vitest/Testing Library and Playwright. No new state library, fake renderer, IndexedDB subsystem or prototype route.

**Inputs:** [Approved spec](../specs/ascii-magic-rebuild.md), umbrella Task3, [approved design](../design/screens/ascii-magic-rebuild/design.md), [tokens](../design-config.md), [Characters profile plan](ascii-magic-character-style.md), `docs/research/ascii-magic/2026-10-20/{desktop-measurements.json,panel-lifecycle-evidence.md,font-embedding-evidence.md}`, and fixed1440/1920 screenshots. The full rebuild remains in scope; this is delivery order, not permission to omit later families/workflows.

## Controller and resource contract

```ts
type StudioView = {
  zoom: number; compare: boolean; catalogWidth: number; catalogCollapsed: boolean;
  dockOpen: boolean; dockCollapsed: boolean; activeGroup: "characters" | "color";
  mobileSheet: "styles" | "controls" | null;
};
type PaintedIdentity = { sourceId: string; sourceRevision: number;
  projectId: string; revision: number; calibrationId: string };
```

Controller methods: `loadFile`, `loadOwnedDefault`, `patchParameter`, `beginEdit`, `commitEdit`, `undo`, `redo`, `setView`, `exportStill`, `cancelExport`, `retryRenderer`, `dispose`. Browser resources are private handles, not project JSON/history; snapshots expose project, view, loading/error/status and latest accepted frame identity. Each validated project/look mutation increments a monotonically increasing revision; view/favorites/search/panel changes do not. Undo/redo also increment revision rather than returning to an old identity.

On render, capture project/source/revision/atlas identity, call `prepareCharactersProject` plus the real `renderCharactersPreview`, then paint only if every captured identity still matches and this controller generation is live. Increment/dispose generation on replacement/unmount; abortion is an optimization, identity checks remain authoritative. An export result is never painted into the preview. Original comparison uses the same retained original source and fitting transform; release Compare on pointerup/cancel/window blur or keyboard release, with a separate accessible toggle for touch/keyboard.

Store at most50 history entries, containing only validated look/crop/rotation snapshots for the current source. Range pointerdown/keyboard sequence begins one edit; intermediate patches render immediately; pointerup/cancel/keyup/blur commits one history entry. Custom ramp has a local draft; invalid/partial Unicode never replaces the last valid render. A valid edit session commits once at blur/Enter. Ctrl/Cmd-Z and redo work outside editable inputs; native text-entry undo remains untouched in inputs/textarea/contentEditable. Toolbar Undo can explicitly commit the current edit before undoing. No-op edits create no history.

## Local-source and export policy

- First upload formats: signature-validated PNG/JPEG/WebP/BMP using the existing `inspectImage` header logic with stricter supplied limits, not MIME/extension alone. Reject user SVG/XML/HTML/GIF/video in this milestone before decoding; no external URLs/pasted HTML. Clipboard reads only image file items. The known original same-origin botanical SVG has a separate trusted asset path after static audit of script/foreignObject/external href/CSS/font references; never route arbitrary SVG through that exception.
- New decoder retains the original EXIF-oriented dimensions and full sRGB/straight-alpha pixels. Existing `src/converter/image.ts::decodeImage` silently shrinks to1600px, so do not reuse it for Studio output or change its legacy behavior. Use createImageBitmap with orientation when available; bounded local Blob/Image fallback revokes URLs and clears image src. Check decoded dimensions again, including swapped EXIF axes, before source upload. Always close ImageBitmap in finally, including obsolete/error paths; reset owned decode canvases.
- Initial conservative limits: encoded bytes<=12MiB, source side<=8192, pixels<=4,000,000; these are a visible first-delivery admission policy under the broader core limits. Before bitmap/canvas/readback allocation, preflight known controller-held old source/frame plus encoded bytes and at least five new RGBA equivalents (decode backing/readback and service recovery/transfer allowances) against192MiB for this source pipeline. Document browser/native allocator uncertainty and independent WASM/calibration/output budgets; this is not a universal heap cap. Reject without downsizing; later measured limits may widen.
- One decode is active, one newest pending file reference; replacing/canceling marks old work obsolete but does not free its reservation until its noncancellable promise really settles. Recheck cancellation after file read, decode and upload. Serial source replacement must not leave the worker holding an uncommitted stale source: on obsolete upload acknowledgement restore the last committed source before more preview work, or commit the newer pending replacement transaction first. Failed decode/upload preserves the last successful source/project/frame. Drop stale file/blob/pixel references promptly; ordinary rendering makes no network requests containing source bytes.
- Export captures immutable project/source/revision, calls the real full-frame `renderCharactersExport` at scale1/2/3/4 and uses its dimensions, not the display canvas, fit size, zoom or adaptive preview. Preflight source/session profile scratch, actual atlas, output frame and encoding canvases; disable scale choices with exact unavailable reason when memory/backing/codec bounds fail. Do not promise every source can export4×. During source replacement cancel the old export; look changes may continue while the captured same-source export finishes.
- PNG preserves the Rust frame's alpha/full margins. JPEG explicitly flattens onto black (show that choice in the popover) using source-over on a separately budgeted opaque encoding canvas. Do not add a “transparent” toggle that silently changes the fixed backdrop/look; alpha in the current Rust output is what PNG preserves. Native toBlob encoding may not cancel: discard late canceled blobs, never download them, and release canvases/URLs when settled. Verify returned MIME/signature; null/unsupported fallback is an error, never rename bytes. Revoke download URLs after use/unmount.
