# Studio completion execution contract

User direction: execute the existing approved full rebuild continuously, prioritizing the three existing styles, Dither and spatial Braille. Existing approved specification, design and initial-family plan remain authoritative. This document records integration order, not reduced scope or a replacement architecture.

## Design

Keep the accepted neutral Studio shell and its responsive sheets. Rust/WASM owns numerical rendering. Controls, validation, recipes and Flow consume the same typed registry. Extend capabilities additively; the frozen Characters context v1 and existing saved projects retain their behavior. A new control must affect preview and captured export identically. Unconfigured optional network services must explain their state, never simulate a successful response.

Independent renderer profiles must be identified as such until same-input reference comparisons establish equivalence. Capture matching source dimensions, crop, rotation, settings, reference output and local output; inspect alpha, partial cells and exports. Do not infer factory defaults from a reused reference session.

## Execution sequence

1. Complete native spatial Braille using the existing closed Task 7 contract; verify all patterns, threshold/alpha semantics, partial cells, crop/rotation/scale, bounded work, admission and release. Rebuild actual WASM, independently review, then integrate calibration, controls, capability availability and browser tests.
2. Extend existing styles through an additive context capability: backdrop none/solid/original/blur, softness/opacity, glyph or tile opacity, mapping inversion, coverage and supported blend modes. Keep v1 byte layouts and historical baseline behavior. Test each meaningful control against neutral/transparent/nondivisible synthetic inputs and equal preview/export scale. Record same-input reference differences explicitly.
3. Close independently specified Dither payload/algorithms and add real ordered Bayer and diffusion jobs; then complete remaining initial-family contracts/renderers (Mixed, Block, Dots, Cross, Diamond, Lines, Diagonal, LEGO, Voxel, Disco). Each family needs distinguishing numerical fixtures, worker capabilities, controls and real output acceptance before ready status.
4. Add native post-frame operations for vignette, scanlines, bloom, chromatic aberration, CRT, glitch and grain. Use the reference fixed pipeline order, seeded noise, bounded scratch/admission and cooperative cancellation. Export captures the full operation stack. Preserve effects when switching styles and include them in whole-look history.
5. Enable crop/rotate UI using existing normalized geometry; support free and standard aspect ratios, cancel/reset/apply and undo. Implement scaled text overlays last in composition, then masks and lighting with explicit source/asset ownership and project persistence.
6. Connect video frame decoding and animation time to the same render service with latest-frame backpressure, playback controls and cleanup. Use existing GIF/WebM encoder infrastructure after actual processed-frame integration; MP4 capability must be detected and produce actual MP4 bytes. Cancellation and disposal release decoding/recording resources.
7. Connect saved looks and library using existing storage where compatible. Recipes serialize validated settings without source pixels; projects restore source assets transactionally. Inspire changes source/look, Restyle only look, Shuffle only source. Include undo, storage failure and unavailable-asset recovery.
8. Build Flow as source/style/effects/output nodes over the same project/engine. Validate edges, cycles and connectivity; support editing, positions, pan/zoom, selection/deletion, undo and save/load. Workspace switches retain the project. Add advanced families only through genuine renderer contracts; finish mobile interaction, browser/resource/performance checks and configured optional service adapters.

## Verification and review

For each implementation task: observed failing behavioral test, implementation, focused passing tests, independent specification and quality review, fix loop. Preserve pre-existing dirty files and raw research. Shared production interfaces have one implementation writer at a time. No branches, commits or pushes are required by this request. Run bounded full JavaScript, native, TypeScript, lint, production build and relevant actual-worker browser tests at integration boundaries. Numerical tests alone do not establish reference parity. Full completion requires all requested surfaces to operate in the new Studio.

## Interface checks

| Producer → consumer | Contract to preserve |
| --- | --- |
| Native family → wire/service | Dispatch, exact payload, atlas identity, dimensions and frame ownership |
| Service → runtime | Current source/project/style/revision identity, cancellation and terminal reservations |
| Registry → UI/project/recipes | Same defaults, bounds, parameter keys and readiness |
| Runtime → preview/export | Same pixels at equal scale; captured look survives later editing |
| Controller → tools/library/Flow | Whole-look history and transactional source restore |
| Media → runtime | Timestamped frame ownership, bounded latest-frame scheduling |

Ruling: the user's “do it one go” authorizes continuous implementation of the already approved design without repeating confirmation gates. It does not authorize inventing reference behavior or reporting partial work as complete.
