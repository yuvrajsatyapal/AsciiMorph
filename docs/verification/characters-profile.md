## Native glyph layer

## Task 3 — additive profile ABI and persistent service, 2026-10-22

The glyph-layer profile is now available through Rust/session/WASM and separate service methods `setAtlas`, `renderCharactersPreview`, and `renderCharactersExport`. It remains an intermediate **None context only**. Solid/Blur return an explicit request-scoped capability failure; no Characters registry binding, project adapter, Studio UI or complete reference-look readiness is supplied. Profile ABI version1 does not imply full backdrop context support. Task4 must add an explicit full-context capability before Task5 may bind the complete look; a Task3 binary must remain visibly insufficient.

The legacy160-byte settings layout and old packed-grid block are unchanged. Optional profile capability requires all four additive exports together: `render_characters_profile_version()->1`, `render_begin_characters_v1`, `render_frame_output_ptr`, and `render_frame_output_len`. Missing/partial optional exports leave legacy rendering usable. Existing output exports refuse profile jobs; frame output exports refuse legacy jobs. Step/cancel/release dispatch both typed job variants.

Profile settings are exactly112bytes: eight little-endian u32 `[v,W,H,rotation,count,backdropKind,solidRGB,spaceIndexOr65535]`, then ten f64 `[F,S,B,C,cropX,cropY,cropW,cropH,originX,originY]`. Offset28 carries exact literal-space identity; absent space is65535. None/Solid/Blur kinds are0/1/2; this stage numerically accepts only None and requires solidRGB0. Count2..256, actual mask extent/origin and source-derived geometry are checked. Frame header is exactly32bytes, eight u32 `[v,W,H,columns,rows,rgbaOffset,gridOffsetOr0,totalBytes]`, canonical contiguous RGBA from32, then the unchanged packed-grid block with offsets relative to its own start. A zero-area floor grid preserves its separate column/row counts (e.g2×0) but has gridOffset0 and grid:null. Truncation, excess bytes, noncanonical offsets, overflow and nonzero packed alignment padding are rejected before result arrays are copied.

Native and real WASM fixtures independently expect the same bytes for literal space versus a distinct empty dot, fractional negative/positive origin masks, full margins, null grids and cropped/rotated S2 flat-probe output. No encoder/decoder-only round-trip substitutes for these expectations. Exact Task1 source-aware settings/frame validators are used at wrapper, worker and service boundaries. Profile transport carries a closed SourceRef and matches id/revision/dimensions to retained source geometry. Atlas identity includes origin, space, placement, ordering, font policy and complete calibration identity. No runtime source/mask clones occur per frame. Service snapshots caller source/atlas once for recovery and transfers new upload snapshots; frame results own arrays detached from growable WASM memory.

Rust calibration retains actual mask dimensions and shares its `Arc<Vec<u8>>` mask allocation with a short-lived checked reference atlas view. Jobs hold only numeric pointer identity/metadata. The single underlying mask capacity is charged once; all other calibration capacities, source capacity, stages, retained jobs, output capacity, metadata and the largest required next serialization are admitted together. None's conservative peak uses8bytes/framepixel+28bytes/cell plus header/job/source/atlas metadata and other retained allocations. Serialization writes the packed grid directly into the single final frame block without an additional grid staging clone. Failed source/calibration uploads preserve old jobs/state; successful source uploads invalidate every dependent job; successful calibration/atlas uploads invalidate glyph/profile jobs while preserving calibration-independent Braille.

Actual production channel scheduling and the browser diagnostic are recorded in [worker-yield-diagnostic.md](worker-yield-diagnostic.md). Focused final validation: native72tests, TS107tests across9files, real-WASM post-build tests, typecheck and scoped lint. These checks preserve legacy retention/recovery/latest-preview/export-queue/fairness/cancel/fatal/dispose invariants and exercise their profile variants. The modeled budget is not measured process RSS, JS heap, OS font memory or a complete pipeline memory proof. Browser recovery/caller snapshots are separate from the WASM session-owned budget.

Integration limit: the engine retains one shared source and one atlas. A changed source cancels all active dependent jobs; a changed font/ramp/atlas cancels active exports as well as previews. Parameter changes sharing the same atlas can use concurrent lanes. The later shell must expose this behavior or deliberately add per-job retained atlases before promising that every look change can continue alongside an already captured export. ## Task 4 — complete fixed backdrop context, 2026-10-22

The actual profile dispatch now returns Rust-composited full frames for None (transparent backdrop), Solid (opaque black), and Blur (original source, fixed blur8/opacity100). Project adapter/registry binding (Task5), Studio UI, additional controls and complete reference parity remain pending.

Complete-context capability is explicitly **separate** from the112-byte profile wire version. Optional `render_characters_context_version()->1` is exposed only by the complete implementation. The wrapper exposes `charactersContextVersion:1|null`, alongside glyph-only `charactersProfileAvailable`. The worker's closed `ready` response separately reports optional `charactersProfileVersion` and `charactersContextVersion`; the service exposes both as1/null while ready and null otherwise. Missing old readiness fields remain compatible. Missing/unknown context version, or a partial profile export set, cannot advertise full readiness. Backdrop geometry shares the glyph job's validated floor/ceil crop and inverse quarter-turn pixel lookup, including empty-derived-crop rejection. At destination pixel center, prepared coordinates are `(x+.5)/S-.5` and `(y+.5)/S-.5`; bilinear taps clamp to the prepared edge. Source straight alpha is premultiplied before interpolation. Three horizontal/vertical moving-box pairs operate on f32 premultiplied RGBA planes with f64 running sums. Ordered radii for S1..4 are `[7,7,8]`, `[15,15,16]`, `[23,23,24]`, `[31,31,32]`. Three-times variance is respectively184/752/1704/3040; integer variance-error ties select more lower widths. The S1 impulse has independently counted coefficients183/3825 at center,120/3825 at offset8 and1/3825 at offset22; native tests check both unquantized premultiplied values and rounded output bytes. Edge-clamp tests independently enumerate convolution paths. Hidden alpha0 RGB cannot bleed; final byte-alpha0 canonicalizes RGB0. The existing straight-alpha glyph layer is composited source-over in Rust. This is an independently specified bounded Gaussian approximation, not exact browser/reference blur equivalence.

Admission conservatively reserves **at least48bytes/framepixel for every complete-context job**, plus28bytes/cell, headers, source/atlas/job metadata and all other retained jobs/stages/outputs. Source and actual shared atlas capacity are charged once. Active jobs retain their future allocation reservations globally; a second job, stage or replacement upload cannot consume another active job's scratch/serialization headroom. This intentionally tightens old staging behavior: an unsafe stage now fails early with BudgetExceeded, preserving jobs, rather than succeeding and blocking their later serialization. Actual buffer capacities are checked after allocation, including capacity surplus in the retained reservation and final output capacity. Failed admission/replacement preserves previous state; cancel/replacement/dispose releases the dependent job and its reservation.

Each Blur job exclusively owns two f32RGBA planes (32N bytes) and the glyphRGBA (4N). Resizing writes directly into the first plane; there is no separate prepared-image allocation. The second plane is released after the final blur pass, the first after composition, before final serialization. The existing glyphRGBA becomes final frameRGBA without a clone. Serialization temporarily retains frameRGBA plus its final serialized copy (8N total) and packed grid; the48N floor remains conservative despite these disjoint peaks. Null-grid cases and partial-cell margins still retain complete backdrop pixels. The budget is a conservative owned-buffer model, not process RSS/JS heap/OS font memory. As before, fixed registry/BTree bookkeeping is bounded separately to16sessions/instance,2jobs/session and1stage/session; profile inline metadata is included in its estimate. Browser upload/recovery snapshots and caller-owned result buffers remain outside the WASM-session budget.

One numerical work unit handles one glyph unit, one four-tap resize pixel, one moving-window output, or one final composition pixel. Initial window sums perform at most65 fixed taps at S4; rows/columns are never single work units. All phases honor cancellation and immutable identity guards. Production retains the existing4ms/64-step scheduling policy (4096 work per step). Admitted vector initialization and final serialization copies are synchronous, so this is not a hard4ms whole-call guarantee. CPU implementation acceptance does not select the final GPU/backend architecture.

## Task 5 — exact four-control project binding, 2026-10-22

`prepareCharactersProject(project, scale, atlas, resources)` now validates and detaches a complete saved project, then prepares the strict source/settings/context/binding payload. It accepts only canonical `characters` with exactly `fontSize`, `charSet`, `brightness`, and `contrast`. It rejects effects even when disabled, masks, text, Flow graph presence, extra keys and legacy controls. Source identity/revision/dimensions must match the uploaded resource. Crop uses floor/ceil pixel bounds followed by quarter-turn rotation; explicit scale derives the full frame without changing the saved project. Controller job IDs/revisions remain outside `RenderProjectV1`; source revision is separately preserved.

The resources contract is `{ source, calibrationId, fontFamily, fontRevision, charactersProfileVersion, charactersContextVersion, memoryBudgetBytes }`. Both profile and **complete context** must be version1. Old profile-only WASM, missing/stale source/atlas/font identities, malformed measured keys and insufficient complete-frame budget fail visibly. Preflight reserves source plus measured atlas backing,48bytes/framepixel,28bytes/cell and4096bytes overhead. Other live jobs, staging, capacity surplus and authoritative aggregate admission remain worker checks; this is not process RSS or whole-browser memory accounting.

Call `prepareCharactersGeometry(F,S)` before calibration. It returns font pixel size `F*S`, cell width `(.6*F)*S` and cell height `F*S`. This exact arithmetic matters at S3: F3.2 gives cell width5.76; `.6*(F*S)` instead gives5.760000000000001 and is correctly rejected as a different identity. Finite fractional font sizes are preserved. `readReferenceCalibrationIdentity(atlas)` reads the closed version1 key at the calibration boundary: profile/order/placement/policy/family/font pixels/revision plus measured mask dimensions and wrapper origins must agree. Matching cells cannot hide masks drawn at the wrong actual font size. The controlled stack remains exactly `"Courier New", Courier, monospace`; verified-family fixtures remain supported under the existing loaded-FontFace policy. No installed-Courier or exact-reference-font claim is added.

Only canonical Characters is bound: Rust CPU dispatch1, complete `rgba` output. Every existing shader schema remains unbound/unavailable. The optional grid is metadata; it cannot represent the final blurred backdrop by itself. Full Characters parity stays **Open** in the parity ledger.

## Studio Task 2.5 — bounded captured atlas ownership, 2026-10-22

Successful atlas/calibration replacement now preserves active Characters profile jobs against their original immutable measured calibration. Native profile jobs pin `Arc<GlyphCalibration>` and reconstruct the borrowed reference atlas from that capture on every step. Numeric completion drops the native calibration capture after serialization; cancellation, source replacement, session disposal and release retain their existing ownership semantics. Legacy glyph jobs still invalidate on successful calibration replacement; calibration-independent Braille remains usable. No source/mask copy is made per numeric job or frame, no numerical glyph/blur operation changed, and the legacy160-byte/profile112-byte/frame32-byte wire layouts and context1 are unchanged.

Optional `render_characters_atlas_retention_version()->1` is separate from profile/context capability. The wrapper, closed worker `ready` response and service expose `charactersAtlasRetentionVersion:1|null`. Missing/unknown retention exports or partial profile exports cannot claim independence. Such modules retain documented old cancellation behavior; after a successful upload the wrapper also cancels any profile handles retained by an unadvertised newer module, accepting only cancelled or already-absent/InvalidInput status and propagating traps/unexpected native statuses. New wrappers keep captured profile dictionaries/origins/literal-space identity across replacement and decode frames with each job's captured atlas. Failed upload admission preserves usable current state and captures.

The worker separately tracks latest logically accepted atlas/calibration and currently selected engine input. Each admitted profile task references its immutable upload snapshot, including the lazy active export and one pending export. Before a numeric handle is created, the engine selects that captured atlas if needed; validation of new preview requests still uses logical latest identity. Native profile handles survive these checked reuploads. Both internal selection and logical replacement explicitly settle displaced legacy glyph tasks as `cancelled`; a later legacy request restores the latest full logical calibration before beginning. The service's per-request waiter validates returned profile frames against its captured atlas, while recovery keeps only latest logical input. A fatal worker failure rejects active/pending captures; retry creates a new worker and restores latest input rather than resuming old exports.

Native admission includes all unique reachable current/active captured calibrations, existing numeric/output vectors and each active job's reserved future peak before staging, replacement or a second profile begin. For each unique calibration allocation it charges `coverage.capacity()*4 + shapes.capacity()*4 + size_of::<GlyphCalibration>() + 2*size_of::<usize>()` (the struct and Arc counters); each unique mask allocation separately charges `masks.capacity() + size_of::<Vec<u8>>() + 2*size_of::<usize>()`. Shared mask Arcs are counted once even across distinct calibration structs; actual distinct equal-valued allocations are charged separately. Capacity surplus is retained in this accounting. At most three calibration and mask allocations are reachable from a session: current plus two native profile captures; a checked replacement adds one transient allocation and its one upload stage. The inline Arc references, session/stage/job BTree nodes and allocator bookkeeping remain separately bounded fixed bookkeeping (16sessions/instance,2jobs/session,1stage/session), rather than measured allocator/RSS accounting. This is the existing conservative owned-buffer model, now including calibration ownership/control blocks; it is not total process memory.

Browser/service/worker retention is separate from that native budget. Once requests are admitted, the worker has at most three task captures (preview,active export,pending export) plus one latest logical input; each profile atlas is limited to16MiB. Captures share upload snapshots and allocate no per-job mask copies. Wrapper upload selection takes its own immutable snapshot, bounded by current plus two native job dictionaries; reselection can create a distinct checked native allocation and wrapper snapshot even when its values equal an older one. The service retains latest recovery input plus references from unsettled admitted requests. Existing caller-owned snapshots, queued public input operations/in-flight transport messages, transient upload copies, result buffers, JavaScript object/string overhead, browser font memory and OS allocations are outside the WASM session budget; no universal JS heap/RSS bound is claimed.
